# Отчёт по Bybit Card

Vite + React + TypeScript + shadcn/ui. Выгружает всю историю операций по карте Bybit
через `POST /v5/card/transaction/query-asset-records` и строит статистику по дням и
месяцам — всё в USD.

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:5173, введите **API Key** и **API Secret**. Пара сохраняется в
`localStorage` этого браузера, выгруженная история кэшируется там же — при следующем
открытии отчёт строится из кэша, кнопка «Обновить» перекачивает историю заново.

> Запросы уходят на `https://api.bybit.com` прямо из браузера: эндпоинт отдаёт CORS-заголовки и
> разрешает заголовки `X-BAPI-*`. Локальная разработка и статическая сборка идут одним и тем же
> путём. Если CORS когда-нибудь перестанет работать, есть запасной вариант: в `vite.config.ts`
> оставлен прокси, включается через `VITE_BYBIT_BASE=/bybit npm run dev`.

## Публикация на GitHub Pages

В репозитории лежит workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml): он
собирает проект и публикует `dist` при каждом пуше в `main`. Базовый путь вычисляется из имени
репозитория, поэтому и `user.github.io/<repo>/`, и `user.github.io` работают без правок.

Что нужно сделать один раз: в настройках репозитория **Settings → Pages → Source** выбрать
**GitHub Actions**.

Прод работает без сервера, потому что запросы идут напрямую в Bybit. Стоит держать в голове две
вещи:

- Ключи живут в `localStorage` браузера каждого посетителя, на страницу они не «зашиты» —
  опубликованный сайт своих ключей не содержит. Но кто угодно с доступом к репозиторию может
  подменить страницу и начать собирать чужие ключи, так что доступ на запись стоит держать узким.
- Кросс-доменно браузеру виден не весь ответ: в `Access-Control-Expose-Headers` у Bybit только
  `token` и `X-Signature`, поэтому `X-Bapi-Limit-Reset-Timestamp` прочитать нельзя и бэкофф при
  лимите работает чисто экспоненциальный, без подсказки о моменте сброса.

## Как это устроено

- [`src/requests/`](src/requests) — слой обращений к API. Чёрный ящик: принимает тело запроса
  ровно в том виде, в каком его описывает эндпоинт, и отдаёт `result` как его прислал сервер,
  без подстановки умолчаний и переименования полей. Внутри — подпись, `fetch`, распаковка
  конверта и `BybitApiError` на любой сбой. Один файл — одна сущность (тип, константа, функция),
  наружу всё идёт через [`src/requests/index.ts`](src/requests/index.ts) поимённо, без wildcard.
  Серверные типы живут только здесь: [`CardAssetRecord`](src/requests/types/CardAssetRecord.ts)
  описывает запись как она приходит, со всеми особенностями. Новые эндпоинты добавляются
  отдельным файлом рядом с [`queryAssetRecords.ts`](src/requests/queryAssetRecords.ts) и строкой
  в индексе.
- [`src/lib/bybit.ts`](src/lib/bybit.ts) — оркестрация поверх этого слоя: последовательный обход
  страниц. `limit: 100` (технический максимум), `page` увеличивается, пока не придёт неполная
  страница или не наберётся `totalCount`. Статистика считается только после того, как собрана
  вся история.
- **Лимит запросов.** Эндпоинт отвечает `retCode 10006` довольно быстро, поэтому пауза между
  страницами адаптивная: старт 350 мс, и каждый отказ увеличивает её в 1.8 раза (до 5 с) на весь
  остаток выгрузки. Сама отклонённая страница повторяется с экспоненциальным бэкоффом
  (1.5 с → 60 с, до 7 попыток), а если ответ принёс заголовок `X-Bapi-Limit-Reset-Timestamp` —
  ожидание тянется до указанного момента. Во время паузы в интерфейсе идёт обратный отсчёт.
- [`src/lib/stats.ts`](src/lib/stats.ts) — нормализация записей и агрегация по дням/месяцам.
  USD-сумма берётся из первой пары «сумма + валюта», где валюта равна `USD`
  (`basicAmount`/`billAmount`/`transactionAmount`/`paidAmount`). Записи без USD-суммы в
  статистику не попадают, их количество показывается отдельным предупреждением.
- Возвраты определяются по `side`/`status`/`tradeStatus` и по отрицательной сумме; в
  статистике они идут отдельной строкой и уменьшают «чистые» траты.

## Что в интерфейсе

- **Календарь** — месяцы года от свежего к старому (декабрь → январь), будущие месяцы не
  показываются; каждый день закрашен по сумме трат (5 ступеней,
  границы — квантили по всем дням истории, поэтому цвет означает одно и то же в любом году).
  Наведение показывает сумму и число операций, клик раскрывает список операций за день.
- **Месяцы** — суммы, число операций и средний чек по месяцам. Полоса каждого месяца составная:
  её длина — величина трат относительно самого дорогого месяца, а сегменты — доли категорий.
  Клик раскрывает месяц: метрики, пик дня и разбивка по категориям с суммой, долей и числом
  операций; оттуда же кнопка в таблицу с фильтром по месяцу. Категория раскрывается дальше — в
  список мерчантов с суммой, долей внутри категории и числом операций, до 8 строк, остаток
  сворачивается в «ещё N». Если у мерчанта был возврат, он подписан рядом отдельной суммой.
- **Вид операции.** Поле `side` — числовой код, а не слово:
  [`src/lib/side.ts`](src/lib/side.ts) держит документированный enum
  (`3` — покупка, `5` — возврат, `6` — чарджбэк, `13` — снятие в банкомате и так
  далее) и раскладывает коды на три направления: списание, возврат и «холд».
  Холды — это авторизации и заявки (`1`, `2`, `10`, `11`): они видны в списке
  операций, но в суммы не входят, иначе удвоили бы собственное списание.
  Коды вне документации разбираются запасной эвристикой по тексту статуса и
  знаку суммы. Там же лежат enum-ы `tradeStatus` и `status`.
- **Формат данных.** API типизирует числа вольно: `txnCreate` и `uid` приходят
  строками, суммы бывают в научной нотации (`0E-8`), а `merchName` и `merchCity`
  дополнены пробелами справа. Всё это нормализуется при разборе, поэтому типы в
  [`src/lib/types.ts`](src/lib/types.ts) описывают реальный ответ, а не
  идеальный. Значение `type: SIDE_QUERY_FINANCIAL_ALL` в запросе не описано в
  документации (там перечислены `SIDE_QUERY_AUTH`, `SIDE_QUERY_FINANCIAL`,
  `SIDE_QUERY_REFUND`), но именно оно возвращает покупки и возвраты вместе.
- **Категории.** Bybit присылает категорию мерчанта голым MCC (ISO 18245) — четырёхзначным
  кодом в `mccCode` и `merchCategoryDesc`. [`src/lib/mcc-data.ts`](src/lib/mcc-data.ts) содержит
  вшитый справочник всех 981 кода (датасет [greggles/mcc-codes](https://github.com/greggles/mcc-codes),
  Unlicense / public domain) плюс правила свёртки кодов в 22 понятные группы: «Продукты»,
  «Кафе и рестораны», «Транспорт», «Топливо», «Путешествия» и так далее. Явные коды имеют
  приоритет, остальное разбирается по отраслевым диапазонам ISO 18245. Графики агрегируются по
  группам, а в таблице транзакций видна точная расшифровка кода и сам MCC; по ним же работает
  поиск, и они попадают в CSV. Справочник пересобирается скриптом
  [`scripts/generate-mcc.py`](scripts/generate-mcc.py), править файл руками не нужно.
- **Цвета категорий** раздаются один раз по всей истории — топ-7 категорий получают слоты
  фиксированной палитры (проверена валидатором на различимость при дальтонизме в обеих темах),
  остальные красятся нейтрально-серым. Категория держит свой цвет во всех месяцах, то есть цвет
  привязан к категории, а не к её месту в рейтинге конкретного месяца. В составной полосе серый
  хвост сливается в один сегмент «Прочее», но в таблице месяца категории названы поимённо —
  до 12 строк, дальше остаток сворачивается в «Прочее (N)».
- **Транзакции** — поиск, фильтр по месяцу, выгрузка в CSV.

## Параметры запроса

Тело запроса по умолчанию — то же, что в веб-кабинете:

```json
{ "page": 1, "limit": 100, "status_code": "1", "type": "SIDE_QUERY_FINANCIAL_ALL" }
```

`status_code: "1"` — только проведённые операции. Поле можно переопределить через
`params` в `fetchAllAssetRecords`.
